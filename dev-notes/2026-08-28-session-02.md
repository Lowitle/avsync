# 2026-08-28 — Session 02

## Goal

Fix a real-world regression found while batch-processing "Everybody Hates
Chris" S01: audio desync in the last ~1 minute of episodes, traced back to
sparse audio anchors near the end of the file. Improve anchor density/
precision in general, and add tooling to inspect anchor coverage per episode.

## Context

Batch run over the full season (`AVSync_batch.py`, `--anchor_source audio`,
fixed stream indices 1/1/2, see `dev-notes/README.md` conventions) was
stopped after the user noticed desync in the last minute of 2 episodes.
Root cause hypothesis (confirmed): the coarse 60s-window/30s-step anchor
scan leaves large unverified gaps whenever several consecutive windows fail
the confidence/agreement checks (e.g. quiet passages, compressed/lossy
foreign audio). The final segment before content-end was consistently the
worst offender because there's no anchor beyond the last accepted one.

## Changes made (in order)

### 1. Symmetric tail anchor recovery (`audio_alignment.find_partial_anchor`)
Extended the existing head-only "partial anchor" recovery (used for
mismatched intros) to also run at the tail, via new `reference_start`,
`expected_offset`, and `prefer='latest'` parameters. Wired into
`AVSync_v14.run_audio_pairing_stage` as a new tail-recovery block mirroring
the existing head block. Lowered both head/tail trigger thresholds from
`window_seconds*1.5` to `window_seconds*0.5` so they engage on realistic
gaps (tens of seconds), not just pathological ones (>90s).

### 2. Fixed a real bug in `find_partial_anchor`'s candidate selection
The original algorithm picked the single highest-CONFIDENCE candidate first,
then only looked ±`window_seconds*2` (4s) around it for corroboration -
so it stopped a few seconds into a long, genuinely-matching stretch (e.g. an
identical song outro spanning 60+ seconds) instead of following it to its
true edge. Rewrote to group chronologically-sorted candidates into
contiguous consistent-offset runs, then return the extremal point
(earliest/latest) of the correspondingly extremal eligible run. This is a
correctness fix, not just a tuning change - validated against E02's real
outro (previously anchored at 1179s, now correctly extends to 1225.5s).

### 3. Progressive tail interval added to jump-detection
`progressive_intervals` (used by `_progressive_offset_probes` /
`_locate_transition_point` to localize discrete editorial jumps) previously
only covered `[0, first_anchor]` and consecutive anchor pairs - never
`[last_anchor, content_end]`. Added that missing tail interval so a jump in
the closing stretch gets the same precise hard-cut treatment as anywhere
else in the file, instead of being silently smeared across the final
segment's atempo stretch.

### 4. Fixed a real cache bug: replacement/editorial state lost on cache hit
`save_checkpoint`/`load_checkpoint` only persisted `visual_anchors_details`,
not the module-level `AUDIO_REPLACEMENT_RANGES` / `AUDIO_EDITORIAL_EDITS` /
`AUDIO_EDITORIAL_SOURCE_TEMPO` globals that `run_audio_pairing_stage()` also
produces. When a cache hit skipped anchor detection entirely, those globals
stayed at their empty defaults, breaking any episode with a silence-fill
gap (i.e. most real episodes) with "Invalid duration (Ref=X, Base=0.000s)".
Fixed by persisting/restoring all three; bumped cache version 14->15 so
stale (incomplete) caches are automatically invalidated instead of silently
misused. **This was the actual cause of the very first batch "failure"
after the session-01 fixes looked correct in isolated testing.**

### 5. Offset-consistency relaxed anchor acceptance (user's proposal)
In the main coarse scan loop: a window below `min_confidence` is now still
accepted (at a relaxed floor of `max(1.0, min_confidence*0.5)`) if its
measured offset matches the already-confirmed running `expected_offset`
within `agreement_seconds` - reusing the already-known-good constant
(FPS-corrected) speed as corroborating evidence instead of requiring each
window to independently prove itself. Logged with an "offset-consistency"
suffix on the method name. Requires at least one full-confidence anchor
already accepted (`have_confirmed_baseline`) before any relaxed accept.

### 6. Interior gap densification (user's proposal, reusing find_partial_anchor)
For any two consecutive final anchors with matching offset (i.e. not
already flagged as a jump) and a gap wider than `2*step_seconds`, run the
same short-window (2s) contiguous-run scan from both edges (`prefer=
'earliest'` from the left, `prefer='latest'` from the right) to recover
extra confirmed anchors inside the gap, shrinking reliance on one long
uninterrupted atempo stretch.

### 7. Anchor diagnostic CSV export (`--anchor_report_csv PATH`)
New CLI flag dumping every scanned coarse window (accepted or not, with
waveform/envelope confidence and offset) plus the final anchor list
actually used, via new `_write_anchor_report_csv()`. Directly answers "can
we inspect all the anchors" - previously only visible via verbose log
scraping.

## Validation

Re-ran S01E02 (the reported failing episode) after each change:
- Before any fix: crashed entirely (cache bug, see #4).
- After #1-4: anchor gap 1140s->1225.5s still had no interior anchor; the
  jump between them got a single hard-cut guess.
- After #5-6: gap partially filled via offset-consistency at 570s, 600s,
  1170s (previously missing); the remaining real jump between 1170s and
  1225.5s got precisely localized to **ref 1197.750s** (a 0.1s hard cut)
  instead of being smeared across a 55.5s span. Confirmed via log:
  `Located precise transition at ref 1197.750s (jump +1.925s)`.

Not yet re-validated end-to-end by ear (user was reviewing the muxed output
when this session's checkpoint was written).

## Open items / not yet implemented

- **User's follow-up idea (raised, NOT yet coded):** `compare_silence_profiles`
  (in `audio_alignment.py`) currently predicts where each reference silence
  should appear in the source using a single global offset
  (`anchor_offsets[0]`, the very first anchor) for the entire file. Since the
  real offset drifts over time, silence-difference detection late in the
  file (e.g. near the 1197s transition) is checked against the wrong
  expected position and likely gets missed/discarded. Proposed fix: interpolate
  the local offset from the two nearest anchors (by time) instead of using a
  single global value. **Not implemented, not tested.**
